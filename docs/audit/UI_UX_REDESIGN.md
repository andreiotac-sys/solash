# UI and UX changes

The development branch adds a reversible home-screen redesign controlled by `NEXT_PUBLIC_SOLASH_NEW_UI`. The new interface is enabled unless the value is exactly `false`. Setting it to `false` at build time restores the previous home layout and styles without touching customer data. Booking and data logic remain shared between both appearances.

The new home header shows the selected agenda date, previous/next day controls, a calendar picker, a return-to-today action, the next customer and time, and quick booking/customer actions before revenue summaries. Working-hour warnings now list the configured windows, and move actions ask before an exception. A confirmation never bypasses an appointment or personal-block overlap. Legacy active status values remain selectable during editing.

`src/app/globals.css` adds scoped dark/gold tokens, calmer surfaces, larger bottom navigation targets, clear keyboard focus, reduced-motion support, and iPhone safe-area spacing. `src/app/layout.tsx` opts into `viewport-fit=cover`. The old styles remain when the flag is `false`. No UI framework was added. The current monolithic `page.tsx` still needs incremental component extraction; the redesign is deliberately limited to the highest-frequency home and booking flow.

At 375, 390, and 430 CSS pixels, the local demo page's measured scroll width equaled the viewport width. Home, booking form, and bottom navigation were inspected; navigation targets measured 52/55/61px in these viewports. The authenticated local Supabase flow used synthetic customers and bookings for customer create/edit and guarded deletion, appointment create/edit/cancel, monthly navigation, and an authorized outside-hours booking. It exposed a real usability defect: an approved booking on a day off was saved but absent from the home agenda. The development UI now shows such reservations in an `Exceptie de program` card with time, customer, service, and edit action. The next-appointment card now shows that appointment's actual time interval, and quick booking keeps the selected date. When Supabase is configured, direct deletion is hidden for customer appointments but remains available for personal blocks. Safari control timed out; real iPhone Safari, PWA installation, VoiceOver, and long-press/drag remain untested. The observed dev server hydration warning due to initial online state was fixed by initializing online state consistently and checking `navigator.onLine` after mount; broader interaction testing remains open.

Before a preview deployment, verify that Vercel preview variables cannot write to production Supabase. The Vercel dashboard required login during this review, so Production/Preview isolation is still unverified. Review the feature flag and test both settings in an isolated environment. The flag is compiled into the client bundle, so changing it in Vercel requires a new deployment; it does not change data or database schema.
